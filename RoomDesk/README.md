## 0.8.1 软件更新与快捷编辑

Windows：“数据与安全 → 软件更新”检查、下载并校验 GitHub Release。结束当前业务后，验证密码并备份，程序退出、覆盖安装和自动重启。旧的 0.7 需要先手动安装本版一次。免安装版也可更新，更新后会在原目录注册为可卸载安装版。

## 常用平台气泡

预订与入住均为自由文本平台输入，最多 40 字。常用气泡初始为线下、携程、美团、飞猪，点击直接填入。输入自定义名称即可用于本次登记，不必先加入常用词。

“管理常用词”可添加和删除气泡，两处共用同一份本地保存的词表（最多 30 个）。重复词会提示；删除验证操作密码，只隐藏快捷词，不修改已填写的表单、已保存的预订或入住记录。再添加同名词可恢复；删除全部气泡后仍可自由输入，重启不会重新补回已删除气泡。

## 预订与入住

点击“办理预订”输入姓名、平台和联系电话（平台可自由输入，也可点选常用气泡）；姓名必填。预订房卡显示预订人，可查看资料或取消。转入住时自动带入姓名、电话及平台，仍可修改。取消/完成入住后清除当前预订资料。

入住默认选中身份证；房间默认价单独显示并自动带入实际售出总价。无默认价时显示“未设置”，须手动输入本次售价。平台随入住记录保存，历史搜索、CSV 和账单 CSV 均包含平台。原有记录平台保持“未登记”；旧示例预订显示“未登记预订人”，不虚构姓名。

数据库采用新增字段升级，保留房态版本、原入住信息和金额。用于展示的 5190 端口使用独立演示库，原 5188 预览数据保留。

## 操作密码、房价和分钟账单

1. 首页 → **数据与安全**：首次由使用者设置 8–128 位操作密码，没有预设密码。修改时验证旧密码。入住记录导出、账单导出、数据备份和删除已退房记录验证密码，可选择验证后 5 分钟免重复输入；连续输错 5 次锁定 1 分钟，重启不会清除锁定。密码以随机盐 + PBKDF2-SHA256（210000 次）保存，不保存明文。
2. **房间管理**：新增房间时可填写默认价格，现有房间可保存默认价格（Windows 点击清单行内“编辑”）。没有设置的房间保持空值。办理入住自动带入默认价格，可修改为实际售出价格；新入住必须填写本次入住售出总价，允许 0 元，最多两位小数。房间默认价修改不会重写历史成交价格。
3. 首页 → **账单**：按入住时间筛选，使用北京时间，起止精确到分钟，包含结束分钟的所有秒。当前按“每次入住的售出总价”统计，包含在住和已退房记录，尚不计算住宿晚数、退款、税费或收款。账单是登记金额汇总，不是发票或收款凭证。预览最多 100 笔，导出 CSV 包含该时段全部记录与合计。

金额以整数分存储和汇总。旧记录没有价格时显示“未登记”，单独计数，不虚构为 0 元或按房间新默认价回填。密码、价格列及删除标记通过可重复执行的增量升级添加，已有房间、房态版本和入住记录保留。

**删除范围**：入住记录中可删除已退房记录，在住记录拒绝删除。密码弹窗说明将从历史列表和账单移除；内部保存删除标记和操作日志，可在维护时恢复。本版未增加物理清空、房间删除或永久擦除功能。

**保护范围**：由 C# 共享服务验证密码，直接调用应用导出/删除接口也会验证；CSV 使用带密码的 POST 请求，旧的免密码 GET 导出入口已移除。密码不放入 URL、不写入浏览器存储。该操作密码不加密 SQLite 文件，也不限制已获本机文件访问权限的人直接读取数据库；目前没有自助找回密码功能。

Mac 页面：`/security.html`、`/billing.html`。Windows 提供对应的数据与安全、账单窗口。真实数据未代设密码；测试密码仅用于临时测试库，不是默认密码。

## 独立房间管理界面

首页右上角点击“房间管理”，进入独立页面（Mac：`/rooms.html`；Windows：独立房间管理窗口）。这里展示房间总数、楼层数量、房型数量和房间清单，支持按房号/房型搜索、按楼层筛选及新增房间。房间总数按清单自动统计。现阶段沿用原有新增功能，未增加修改或删除既有房间的功能。

房态页不再提供新增房间表单；入住、退房、预订、清扫及其他日常房态操作仍保留。新增成功后返回房态总览即可看到新房间，新房间初始为待清扫。Windows 关闭房间管理窗口时会重新读取房态。已有房间和入住记录不受此次界面拆分影响。

## 紧凑房态看板（v0.5）

首页移除固定侧栏和大段说明，将空间留给房间。桌面宽屏每层一行、每行 8 间；早期 24 间示例客房在 1280×720 和 1366×768 的 Mac 浏览器视口中全部可见，统计及右侧操作区也无需滚动。更多房间或较窄窗口会换行/滚动，不隐藏房间。

房号、统计数字与入住人加粗放大。可入住用绿、在住用蓝、预订用黄、待清扫用橙、维修用紫、停用用灰；同时保留文字。待清扫统计包括在住和维修房间。在住房间的待清扫状态会额外提醒。卡片优先显示姓名，完整登记信息仍从详情打开。

Windows 首页同步采用紧凑布局，默认最大化，根据可用宽度切换 8 列或 4 列。Windows 已交叉编译，实际字体、缩放和一屏显示仍需实机确认。

## 房态显示入住人

在住房间卡片和右侧详情显示当前登记的入住人姓名，入住后随房态刷新，退房后移除。未登记客人的旧示例在住房间显示“入住人：未登记”。长姓名在卡片上省略显示，悬停或查看详情可读完整姓名。主页不显示证件号或电话。

## 历史住客匹配

入住窗口保留姓名和证件号码的历史下拉匹配，支持上下键选择、回车填入。选中后填入姓名、电话和证件信息；不会覆盖本次预订平台、售价或备注。历史证件类型为空时默认身份证。

读卡器入口、文本解析接口和 Windows 读卡窗口已移除；证件信息采用手动输入或历史匹配。

## 入住记录与 CSV（v0.3）

首页点击“入住记录”。每次入住登记自动保存，退房只结束本次登记，不删除历史；同一房间再次入住会生成新记录。此前仅有房态、没有登记信息的示例入住不会自动补出记录。

支持按姓名、房号、电话、证件号码或备注搜索，以及全部、在住、已退房筛选。列表每页 30 条，按最新登记倒序；详情可查看证件和备注。Mac 支持输入后自动搜索，Windows 点击搜索或按回车。

“下载 CSV”（Windows 为“导出 CSV”）导出当前筛选的全部记录，包含记录编号、房号、姓名、电话、证件类型/号码、入住和退房时间、状态、备注。并非只导出当前页。时间统一为北京时间。

CSV 使用 UTF-8 BOM，处理逗号、引号、换行及公式前缀。Excel 导入时将电话、证件号码列设置为文本，可以保留前导零和长号码。

本原型以 Lantel 的 C# 桌面代码为基础，复用原始 `Models` 和 `HotelDbContext`，新增共享房态服务、中文 WPF 首页及 Mac 浏览器功能预览。原项目文件保留，原型入口位于本目录，不是原项目的 `MainWindow`。

基线提交：`3550191b505817534f0980c115595968a5a1e468`。保留上游 MIT 许可证；第三方 .NET / EF Core / SQLite 组件适用各自许可证。

## 本地待确认：酒店设置、房间删除与长期运行

房间管理顶部可修改酒店名称；房态首页和页面标题同步显示。房间删除要求操作密码，禁止删除在住或已预订房间。删除后移入“已删除房间”，历史入住和账单保留，原房号保留；恢复后为待清扫。新功能已同步实现 Web 预览与 Windows WPF，未推送或发布。

长期运行采用以下机制：

- SQLite WAL + synchronous=FULL；每个连接都设 fullfsync、外键检查。入住/退房/房态/操作记录在事务中提交，成功提示在提交完成之后。WAL 也是磁盘文件，并非仅保存在内存；不能在运行时只拷贝 .db 当备份。
- 数据库连接关闭即释放，单连接缓存 2 MiB，禁用无限 mmap；临时排序使用磁盘。桌面使用 workstation GC，托管堆预算 96 MiB。该预算只约束托管堆，不能等同于整个应用内存上限。
- 入住列表固定分页（默认 30 条，上限 100 条）；深分页先定位编号，再加载当前页详细信息。操作记录只读最近 100 条；账单在数据库内汇总，预览最多 100 条。
- 三字及以上搜索采用 FTS5 trigram；一、二字使用合并搜索文本的覆盖索引，避免多次全字段扫描。历史住客采用带身份索引的最新记录判断，最多返回 8 人，保留同名不同人的区分。
- CSV 逐行生成到磁盘临时文件，下载/保存使用流；同时只生成一个导出，正常关闭自动清理，异常退出的旧临时文件由维护任务清理。百万条导出允许超过 1 秒，不占用入住事务锁。
- 运行时每 15 分钟检查维护，每天创建一次在线增量备份，保留最近 7 份自动备份。按数据库文件隔离备份目录，手动备份不被轮换删除。每次只拷贝 128 页并让出执行，完成后 quick_check 校验再改名；手动备份同样使用分步拷贝，不长时间持有前台写锁。
- SQLite 自动检查点及定期 PASSIVE 检查点控制 WAL 增长，PRAGMA optimize 维护查询规划统计。遇到长期读事务时检查点不能保证立即压缩日志；不定期删除历史业务数据。
- 发布工作流增加百万条核心延迟和实际 Windows WPF 内存门槛：前台样本最大值须小于 1000ms，进程内存须小于 200,000,000 字节；失败阻止进入安装包发布。脚本为 installer/performance-gate.ps1。本轮没有推送工作流或运行 Windows CI。

验证条件：Apple M2、8GB RAM、macOS；300 间房，初始 1,000,000 条历史入住和 2,000,000 条操作日志，后续测试增加少量记录。包含首次调用，常规查询各 12 次、入住组合 30 次、备份中组合 20 次。该结果是共享 C# 核心进程，不包含浏览器或 Windows WPF 渲染，不代表十年真实运行的保证。

218 项核心检查和 87 项 HTTP / 进程检查通过。强制终止测试验证：已确认提交的名称及房间状态重启后保留；事务中尚未提交的改动回滚；数据库 integrity_check 返回 ok。程序强制退出测试不能模拟硬盘损坏、磁盘谎报同步或所有断电场景。

浏览器实际检查：演示酒店名称保存、首页同步、重启后保留；删除入口打开密码验证并取消；数据与安全显示 WAL/FULL 和自动备份路径。成功删除与恢复及其历史保留由核心/HTTP 检查验证。原业务库现有房间、入住、活动、密码和常用词逐项与修改前备份比较一致。

Windows 项目已编译通过（零警告/错误），但原生界面进程 200MB 和真实 Windows 10 硬件操作延迟尚未验收。已提供发布前自动门槛；仍需在目标 Windows 10、实际房间规模和硬盘条件上复验，不能宣称无条件十年不卡顿。

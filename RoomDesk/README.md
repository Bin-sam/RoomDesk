# 栖间 RoomDesk — Lantel 房态管理原型

## 操作密码、房价和分钟账单

1. 首页 → **数据与安全**：首次由使用者设置 8–128 位操作密码，没有预设密码。修改时验证旧密码。入住记录导出、账单导出、数据备份和删除已退房记录每次都验证密码；连续输错 5 次锁定 1 分钟，重启不会清除锁定。密码以随机盐 + PBKDF2-SHA256（210000 次）保存，不保存明文。
2. **房间管理**：新增房间时可填写默认价格，现有房间可保存默认价格（Windows 选中列表后点击“设置选中房间默认价”）。没有设置的房间保持空值。办理入住自动带入默认价格，可修改为实际售出价格；新入住必须填写本次入住售出总价，允许 0 元，最多两位小数。房间默认价修改不会重写历史成交价格。
3. 首页 → **账单**：按入住时间筛选，使用北京时间，起止精确到分钟，包含结束分钟的所有秒。当前按“每次入住的售出总价”统计，包含在住和已退房记录，尚不计算住宿晚数、退款、税费或收款。账单是登记金额汇总，不是发票或收款凭证。预览最多 100 笔，导出 CSV 包含该时段全部记录与合计。

金额以整数分存储和汇总。旧记录没有价格时显示“未登记”，单独计数，不虚构为 0 元或按房间新默认价回填。密码、价格列及删除标记通过可重复执行的增量升级添加，已有房间、房态版本和入住记录保留。

**删除范围**：入住记录中可删除已退房记录，在住记录拒绝删除。密码弹窗说明将从历史列表和账单移除；内部保存删除标记和操作日志，可在维护时恢复。本版未增加物理清空、房间删除或永久擦除功能。

**保护范围**：由 C# 共享服务验证密码，直接调用应用导出/删除接口也会验证；CSV 使用带密码的 POST 请求，旧的免密码 GET 导出入口已移除。密码不放入 URL、不写入浏览器存储。该操作密码不加密 SQLite 文件，也不限制已获本机文件访问权限的人直接读取数据库；目前没有自助找回密码功能。

Mac 页面：`/security.html`、`/billing.html`。Windows 提供对应的数据与安全、账单窗口。真实数据未代设密码；测试密码仅用于临时测试库，不是默认密码。

## 独立房间管理界面

首页右上角点击“房间管理”，进入独立页面（Mac：`/rooms.html`；Windows：独立房间管理窗口）。这里展示房间总数、楼层数量、房型数量和房间清单，支持按房号/房型搜索、按楼层筛选及新增房间。房间总数按清单自动统计。现阶段沿用原有新增功能，未增加修改或删除既有房间的功能。

房态页不再提供新增房间表单；入住、退房、预订、清扫及其他日常房态操作仍保留。新增成功后返回房态总览即可看到新房间，新房间初始为待清扫。Windows 关闭房间管理窗口时会重新读取房态。已有房间和入住记录不受此次界面拆分影响。

## 紧凑房态看板（v0.5）

首页移除固定侧栏和大段说明，将空间留给房间。桌面宽屏每层一行、每行 8 间；当前 24 间示例客房在 1280×720 和 1366×768 的 Mac 浏览器视口中全部可见，统计及右侧操作区也无需滚动。更多房间或较窄窗口会换行/滚动，不隐藏房间。

房号、统计数字与入住人加粗放大。可入住用绿、在住用蓝、预订用黄、待清扫用橙、维修用紫、停用用灰；同时保留文字。待清扫统计包括在住和维修房间。在住房间的待清扫状态会额外提醒。卡片优先显示姓名，完整登记信息仍从详情打开。

Windows 首页同步采用紧凑布局，默认最大化，根据可用宽度切换 8 列或 4 列。Windows 已交叉编译，实际字体、缩放和一屏显示仍需实机确认。

## 房态显示入住人

在住房间卡片和右侧详情显示当前登记的入住人姓名，入住后随房态刷新，退房后移除。未登记客人的旧示例在住房间显示“入住人：未登记”。长姓名在卡片上省略显示，悬停或查看详情可读完整姓名。主页不显示证件号或电话。

## 历史匹配与通用读卡入口（v0.4）

入住窗口中输入姓名或证件号码片段，可查看最多 8 条历史匹配。选择候选后填入姓名、电话、证件类型和号码，不复制上次入住备注，也不会自动保存入住。支持鼠标选择，以及上下键选择、回车填入、Escape 收起。重复证件优先显示最新登记，同名但证件不同的住客分别显示；无证件时按姓名和电话区分。候选中的证件号码隐藏中间部分，选中后表单显示完整号码以供核对。

“从读卡器填入 · 通用键盘模式”是当前默认接入方式，**仅接收模拟键盘的设备或设备软件输出的文本**，不是所有 USB 身份证读卡器的通用驱动。没有设备时也可以粘贴文本验证。进入接收输入框后刷卡，待输出结束点击“识别并填入”，或按 Ctrl+Enter，再核对入住表单并保存。普通 Enter / Tab 保留为设备的字段分隔符，网页可用 Shift+Tab 离开接收框。接收成功或关闭窗口后清除原始文本；解析动作不写入数据库。

约定输出格式（三选一）：

- 姓名 + Tab、换行、空格或逗号 + 18 位身份证号码，姓名在前。
- 两行带标签文本：`姓名：…` 和 `身份证号：…`（也接受“公民身份号码”“身份证号码”“证件号码”）。
- JSON：`{"name":"…","documentNumber":"…"}`。

仅做字段格式识别，不校验芯片、证件真伪或身份证校验位。无法明确识别、多张卡或包含地址等额外字段时提示失败，不猜测填入。读卡填入会清空原联系电话，以免沿用另一位客人的电话；当前备注保留。设备原始文本不加入入住备注。

后续拿到设备品牌、型号及 SDK 后，在共享 `IdentityCardData` 数据结构基础上增加厂商适配；当前没有实现或声称支持串口协议、USB 芯片直接读取、PC/SC 或厂商 DLL。Mac 已测试的是共享解析代码和网页预览；Windows 程序已交叉编译，读卡器联调、Windows 驱动和实机 UI 仍待验证。

## 入住记录与 CSV（v0.3）

首页点击“入住记录”。每次入住登记自动保存，退房只结束本次登记，不删除历史；同一房间再次入住会生成新记录。此前仅有房态、没有登记信息的示例入住不会自动补出记录。

支持按姓名、房号、电话、证件号码或备注搜索，以及全部、在住、已退房筛选。列表每页 30 条，按最新登记倒序；详情可查看证件和备注。Mac 支持输入后自动搜索，Windows 点击搜索或按回车。

“下载 CSV”（Windows 为“导出 CSV”）导出当前筛选的全部记录，包含记录编号、房号、姓名、电话、证件类型/号码、入住和退房时间、状态、备注。并非只导出当前页。时间统一为北京时间。

CSV 使用 UTF-8 BOM，处理逗号、引号、换行及公式前缀。Excel 导入时将电话、证件号码列设置为文本，可以保留前导零和长号码。

本原型以 Lantel 的 C# 桌面代码为基础，复用原始 `Models` 和 `HotelDbContext`，新增共享房态服务、中文 WPF 首页及 Mac 浏览器功能预览。原项目文件保留，原型入口位于本目录，不是原项目的 `MainWindow`。

上游：https://github.com/GideonLartey/hotel-management-system

基线提交：`3550191b505817534f0980c115595968a5a1e468`。保留上游 MIT 许可证；第三方 .NET / EF Core / SQLite 组件适用各自许可证。

## 已实现

- 按楼层展示房间卡片，按房号、楼层、状态筛选。
- 可入住、预订、在住、待清扫、维修、停用状态及统计。
- 入住状态、清洁状态、维修状态独立存储；在住也可以待清扫。
- 预订、取消预订、入住、退房、清扫完成、维修、停用、恢复。
- 退房和恢复使用后须清扫；在住或预订房间不可维修/停用。
- 新增房间、入住登记弹窗与查看信息、最近 100 条操作记录、SQLite 在线备份。
- 版本校验防止旧页面覆盖新状态；变更和日志在同一事务中保存。
- 初始 24 间示例房间，独立数据库，不读取或改写原 Lantel 数据。

入住时弹出登记窗口：姓名与本次入住售出总价必填，联系电话、证件类型、证件号码、备注选填。保存后才转为在住；在住期间可查看登记信息，退房后结束本次登记。当前每间房登记一位主入住人。已有示例在住房间没有历史入住信息，不会虚构补填。

此原型不创建日期订单，不处理收费、身份核验、门锁、OTA、权限或多终端同步。登记数据保存在本机 SQLite 中。

## Mac 上使用

双击 `start-mac.command`，或者在终端执行 `bash start-mac.command`。等终端显示服务已启动后，浏览器访问 http://127.0.0.1:5188 。保持终端打开，Control-C 停止。

启动脚本会优先使用系统 .NET；本次工作区内也可使用已经放在 `work/dotnet` 的 .NET 8 SDK。把源码移到其他电脑时，需要安装 .NET 8 SDK。

Mac 数据位于 `RoomDesk/artifacts/mac-preview/rooms.db`，备份在相邻 `backups` 目录。服务只监听本机 `127.0.0.1`。默认端口为 5188；若占用，请先关闭旧预览进程。不要同时使用两个预览进程。

**Mac 浏览器页面与 WPF 共用同一个 C# 服务和数据库实现，但界面由 HTML/CSS 实现。Mac 页面不能证明 Windows 字体、布局、缩放、窗口交互或流畅度正确。**

## Windows 10 上使用

从本仓库 Releases 下载 `RoomDesk-Setup-0.6.0-win-x64.exe`，运行安装向导；也可下载 Portable ZIP，解压后双击 `RoomDesk.exe`。该版本为 Windows x64、自包含 .NET 8 的单文件发布；不需另装 .NET SDK。目标是 Windows 10 22H2 x64，实际兼容性需在目标机器确认。

默认数据：`%LOCALAPPDATA%\RoomDeskPrototype\rooms-v1.db`。单文件程序首次启动需展开原生库，首次和后续启动速度可能不同。程序未签名。安装器提供快捷方式和卸载入口，升级及卸载保留数据；本版没有自动更新。安装向导为英文，程序界面为中文。安装器由 GitHub Windows 工作流生成并测试，详情见对应 Actions 日志。

需要指定独立测试数据库时：

```powershell
.\RoomDesk.exe --data "C:\RoomDesk-Test\rooms.db"
```

有 .NET 8 SDK 的 Windows 开发机可运行 `validate-windows.ps1`，它执行共享核心测试、发布 EXE 并打开界面供人工验证。打开窗口不等于验证通过。

## 数据与备份

“数据与安全 → 验证密码并备份”使用 SQLite 在线备份，包含已提交的 WAL 数据。不要只复制正在使用中的 `.db` 文件。

本版提供手动备份，尚无自动备份计划或图形化恢复工具。测试备份时，关闭程序后用 `--data` 指向一份备份副本，确认房态与记录；不要覆盖原数据库。备份完整性已做自动检查，人工恢复流程仍需在目标系统验收。

## Windows 实机验收（尚未执行）

1. 在目标 Win10 x64 机器启动 EXE；记录 CPU、内存、系统版本和首次/再次启动耗时。
2. 在 1366×768、1920×1080 及 100%/125%/150% 缩放下检查字体、卡片、详情与按钮可达性。
3. 完成“可入住 → 入住 → 退房 → 待清扫 → 清扫完成”流程；确认在住不能维修、脏房不能入住。
4. 新增房间、搜索、筛选、滚动；关闭重开后确认房态和日志保留。
5. 备份后用备份副本独立启动，核对房数与最近操作。
6. 在实际房间规模下测量点击反馈、滚动和状态保存。建议暂以点击可见反馈 ≤100ms、保存 ≤300ms、连续操作无明显卡顿为验收目标；这些是目标，不是已测结论。

当前未接入原 Lantel 的登录/预订/财务页面，也未迁移现有酒店数据。正式沿用前需要继续评估上游质量、数据库版本迁移、备份恢复及 Windows 实机结果。
